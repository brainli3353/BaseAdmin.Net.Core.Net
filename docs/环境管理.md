## 连接约定

- 开发连接串（appsettings.json `ConnectionStrings:Default`）→ **dev 库**（现任务书内已含）
- **验收/测试连接串**（appsettings.Test.json 或环境变量）→ **test 库**——验收任务书明确「连 test 库实测，不污染 dev 库」
- 密钥不入库：生产连接串走环境变量注入（红线 5）

## 环境隔离纪律

1. 开发自测在 worktree 内（连 dev 库）——验收前数据可随意，验收后清理
2. **验收实测必须连 test 库**（acceptor 用独立库，防验收写坏 dev 数据）
3. 建表：CodeFirst 增量——dev 库/test 库各自 `[IncreTable]` 增量建表（启动即建）
4. 发布门：push main → `deploy-test.sh`（葫芦宝侧）
5. 环境事实权威：本文档 + `../MainWorkspace/docs/资源与台账/资源清单.md`（服务器资源）

## 容器网络与库边界（2026-10-25/26 实测·现值）

> **本节为现值，优先级高于上文 2026-08-26 的 `172.18.0.3`（历史值）。** 由 `CLAUDE.md` 下沉（2026-10-29 瘦身）；CLAUDE.md 保留库边界判据摘要与指针。

- **容器内 hosts 已漂移（2026-10-25 批 CP e2e 实锤）**：`/etc/hosts` 的 `postgres→172.19.0.10` 与 `redis` 主机名均失效（No route／不可解析）——真实可达 **PG=172.19.0.2、Redis=172.19.0.5:6379**（无鉴权）。
- **⚠ MCP 库边界（2026-10-26 两次误判后补，别再踩）**：`pipeline-db` 与 `db-write` 两个 MCP **连的都不是本仓业务库**——前者是监控库 `pipelinecore`（拿它查 `sys_*` 业务表返回 **0 行**，极易误读成"表不存在"），后者干跑业务表报 `relation ... does not exist`。⇒ **查业务库只有一条路**：`psql -h 172.19.0.2 -U huluyeye -d huluyeye_admin`（密码走 `PGPASSWORD` 环境变量·不回显）。
- **库名实读、不背数**：`huluyeye_admin_log` 库**不存在**（日志四表 `sys_log_op|ex|event|http` 就在 `huluyeye_admin` 主库内）；`huluyeye_admin_test` 是**另一套库**，勿当 dev 库用。一律 `psql -d postgres -At -c "SELECT datname FROM pg_database"` 实读。
- **主键列是小写 `id`（不带引号）**，只有 Pascal 业务列带引号——SQL/DDL 初稿写成 `"Id"` 第一步就翻车（专项件 §10.3 实例）。
- **e2e 起实例的 env 覆盖**：`ConnectionConfigs__0__ConnectionString`（同串换 Host）＋`ConnectionStrings__Redis=172.19.0.5:6379`（G8 后 env 最高优先），勿再信 hosts。
