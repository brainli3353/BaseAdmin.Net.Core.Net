# 开发规范（业务仓适用）

> **适用**：以本框架（`BaseAdminCore` 发布仓）为基座 fork 出的**业务仓**。
> **本件是业务侧的约定源**：框架文档（`框架索引.md`／`框架使用指南.md`／`框架开发参考手册.md`）里出现的「约定 #N」**均指本件对应条**——请先读本件，再按指南写代码。
> **关系**：框架能力只在框架仓演进；业务仓通过 `upstream` 同步，**不改框架面**（约定 7）。

## 0. 三条边界（先看清谁维护什么）

| 面 | 谁维护 | 业务仓动作 |
|---|---|---|
| `src/Core/`、`src/Web.Core/`（框架核心：实体基类、SqlSugar、仓储、鉴权、审计、中间件） | 框架仓 | **只读**。缺能力/有缺陷 ⇒ 提给框架上游修复，再 `upstream` 同步 |
| `src/Web.Entry/`（入口/控制器） | 框架仓 + 业务 | 可加**薄**业务控制器（参数绑定 → Service → `ApiResult`）；`Program.cs`／`appsettings` 结构不改 |
| `src/Business/`、业务前端页、菜单种子 | 业务仓 | ★ **业务唯一落点** |

## 约定 1–14

### 约定 1｜业务代码只写 `Business` 层
业务实体、服务、DTO、业务种子放 `src/Business/`（结构见约定 6）；控制器只做薄路由，业务逻辑不写进控制器；不把业务代码塞进 `Core`／`Web.Core`。详见《框架使用指南》§1、§2。

### 约定 2｜编码：UTF-8 带 BOM ＋ LF
- `.cs`／`.md`／`.props`／`.csproj`：UTF-8 **带 BOM**；
- `.json`：UTF-8 **不带 BOM**；
- 行尾一律 **LF**（以仓内 `.gitattributes` 为准）。
提交前逐文件核对；混入无 BOM/CRLF 会在 .NET 工具链与前端构建上产生杂音。

### 约定 3｜异步规范
- 全链路 `async`/`await`；I/O 一律用异步 API。
- **禁止同步阻塞**：`.Result`、`.Wait()`、`.GetAwaiter().GetResult()`（会死锁/线程饥饿）。
- `async void` 仅限事件处理器；其余用 `async Task` / `async Task<T>`。
- 不丢弃返回的 `Task`（fire-and-forget 必须显式处理异常或走框架事件总线）。
- 长耗时/可取消操作传递 `CancellationToken`（框架服务方法签名普遍支持）。

### 约定 4｜实体与种子用增量标记
- 实体贴 `[IncreTable]`（参与增量建表；存量库自动补新增列）；
- 种子贴 `[IncreSeed]`（增量灌入，可重复执行）；
- **新增列必须带缺省值**（`[SugarColumn(DefaultValue = "...")]` 或属性初值），否则存量库 `ADD COLUMN NOT NULL` 会失败；
- 业务初始数据放 `Business/SeedData/`，不要改框架种子。

### 约定 5｜凭据与敏感信息
- 密钥/口令/连接串凭据**不进仓**：走环境变量或部署侧配置；`appsettings.json` 里不得出现真实密钥；
- 日志与异常**不回显**敏感值（框架出口已有统一脱敏，勿在其外自行拼接密钥）；
- 初始管理员密码首登即改；测试探针账号带可识别前缀并自清理。

### 约定 6｜目录与命名
- 目录按域组织：`Business/Services/<域>/`、DTO 就近放 `Services/<域>/Dto/`、实体放 `Business/Entitys/`；
- **单文件单类**；C# 类型 PascalCase（与类名一致）；
- 表名显式小写（如 `[SugarTable("biz_xxx")]`），业务列 PascalCase；
- 细则见《baseadmin 设计精华参考》§八；不确定时以 `docs/框架索引.md` 的既有结构为准。

### 约定 7｜框架仓是唯一上游
- 框架面（`Core`／`Web.Core`）只在框架仓演进；业务仓用 `upstream` 同步升级；
- 发现框架缺陷：**在上游修**（或提交问题给上游）后同步回来，不在业务仓长期私改框架面（否则升级必然冲突、且行为回不来）；
- 业务仓确需框架级能力扩展 ⇒ 向上游提需求，由上游按框架口径实现。

### 约定 8｜最小必要改动
只做与当前目标直接相关的改动；不顺手重构、不顺手格式化无关文件。存量不合规代码遇到时**只登记**，不在功能批里顺手改。

### 约定 9｜增量更新（禁止整对象覆盖）
更新只写明确允许的字段：DTO → 实体的部分更新**逐字段判空/判改动**，禁止「读出整对象、改一处、整行覆盖」；框架实体基类已用 `IsOnlyIgnoreUpdate` 做代码层配合，业务侧须在服务里保持同口径。

### 约定 10｜异常与错误码
- 规则不满足：`throw new AppException(...)`；请求参数问题：`BadRequestException`；出口统一转 `ApiResult`；
- **新增错误码三步**：`ErrorCodes` 常量 ＋ `Lang.zh-CN.json`／`Lang.en.json` 同键 ＋ 本地化默认值同步（详见《框架使用指南》§45）；
- 不无说明地吞异常；对外信息稳定、可检索、**不泄露堆栈**；前端按 `errCode` 判断、按错误码覆盖文案。

### 约定 11｜复用优先
先用框架既有原语：仓储 `ISqlSugarRepository<T>`、缓存 `ICacheService`、分页 `IPageInput`/`PageConst`（**深页由原语按 pageSize 夹上界、超界得空页；别手写 `(page-1)*size`——int 溢出会报错或静默回第 1 页**）、审计与软删、租户/数据权限过滤器、事件总线、定时任务、导出/导入、代码生成预览、本地化等。**不自行发明平行实现**。

### 约定 12｜验证要求（门前置）
改动后必须做**最小但有效**的验证：
- 后端：`dotnet build src/Web.Entry/AdminCore.Web.Entry.csproj`（业务仓建议对**生产链**开 `-warnaserror`，须 0 警告 0 错误）；
- 前端：`cd web && pnpm typecheck && pnpm build`；
- 测试：受影响范围的测试必须跑（`dotnet test src/Test/AdminCore.Test.csproj`；集成测试需真实 PostgreSQL／Redis，环境不具备时至少跑纯单测并在提交说明写明未覆盖项）；
- 无验证必须在提交说明中**显式说明**，不得含糊带过。

### 约定 13｜文档与索引同批维护
结构性变更（新增/重命名/移动文件、新机制、新配置键/缓存键/Claim）与代码**同批**更新 `docs/框架索引.md`；使用方式变化同批更新 `docs/框架使用指南.md`。业务仓若维护自己的项目地图，按 `docs/项目地图_模板.md` 建。

### 约定 14｜全栈闭环（用户可见端点同批交付）
新增/变更**用户可见** API 端点时，同批完成：
1. 前端 API 模块 + 页面（`web/` 既有视图约定）；
2. **菜单种子**：目录/菜单/按钮权限键与控制器 `[MenuPerm]` **一一对应**；
3. 后端构建 + 前端 `typecheck`/`build` 双门全绿。
豁免仅限：纯机制型变更、内部端点（`/health`、`/hubs` 等）、明确约定"先做后端"——**豁免须在提交说明留痕**。操作步骤见《框架使用指南》§25.5。

## 业务仓起步（fork 之后五步）

1. **接上游**：`git remote add upstream <框架仓地址>`；之后升级用 `git fetch upstream && git merge upstream/main`（见下节）。
2. **建模块**：按《框架使用指南》§2 五步——实体 → 服务（`[Service]` 自动注册）→ DTO → 薄控制器 → 验证。
3. **权限与菜单**：给按钮/菜单定权限键，控制器贴 `[MenuPerm("...")]`，种子补菜单/按钮（约定 14）。
4. **前端**：`web/` 加 API 模块与页面；可参考《可用性审单_框架管理页》里的页面基线要求。
5. **过门**：约定 12 的三道门（后端 build／前端 typecheck+build／受影响测试）。

## 升级与 Breaking 处理

- 先读 `CHANGELOG.md` 的 `### Breaking`（破坏性/行为收紧）段：**逐条按迁移指引核对**，不要只看版本号。
- 同步：`git fetch upstream && git merge upstream/main`。冲突若出现在框架面（`Core`/`Web.Core`）⇒ 说明业务仓改过框架面，应先撤销该改动（约定 7）。
- 升级后回归：后端严格门 ＋ 前端双门 ＋ 受影响范围测试。

## 提交前自检（10 条，逐条过）

1. 只改业务面（`Business`／业务控制器／前端页／菜单种子），框架面零改动；
2. 新端点齐：`[MenuPerm]` 权限键、菜单/按钮种子、前端 API 与页面（或者已留痕豁免）；
3. 新实体有 `[IncreTable]`；新增列有缺省值；新种子有 `[IncreSeed]`；
4. 新错误码三步齐（常量／双语文案／默认值）；
5. 更新逐字段（未整对象覆盖）；
6. 复用了既有原语（未造平行实现）；
7. 无密钥/口令入仓；日志与异常无敏感回显；
8. 编码符合约定 2（BOM／LF）；
9. 门全绿（约定 12）；
10. 文档按约定 13 同批更新（如涉及结构或用法变化）。
