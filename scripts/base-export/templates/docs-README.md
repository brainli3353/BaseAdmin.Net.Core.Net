# 框架文档导航

> 本仓只保留业务开发需要的公共文档。内部立项、研究、验收、环境与过程台账不在基础仓。

## 按目标选读

| 你要做什么 | 先读 |
|---|---|
| 快速启动、了解目录与技术栈 | 仓库根目录 `README.md` |
| **业务开发纪律、提交与验收要求** | **`开发规范.md`（约定 1–14，业务侧唯一约定源）** |
| 找文件、看机制装配点、查常量/缓存键/Claim | `框架索引.md` |
| 写业务代码：实体、服务、控制器、权限、菜单、前端 | `框架使用指南.md` |
| 理解某块框架为什么这样设计 | `框架开发参考手册.md` |
| 追溯零 Furion 改造的设计来源 | `baseadmin设计精华参考.md` |

## 四份权威文档的边界

| 文档 | 回答的问题 | 维护时机 |
|---|---|---|
| `开发规范.md` | 业务侧要守什么纪律、怎么验收 | 约定变化时更新（与框架行为同批） |
| `框架索引.md` | 东西在哪里 | 新增/重命名/移动文件、新机制、新缓存键/Claim/ConfigId 时同批更新 |
| `框架使用指南.md` | 怎么用 | 使用方式或开发约定变化时更新 |
| `框架开发参考手册.md` | 为什么这样设计 | 框架级设计与实现变化时更新 |

四者互不重复：开发规范负责纪律与验收，索引负责定位，指南负责操作，参考手册负责设计依据。

> ⚠ **编号约定**：框架文档正文里的「约定 #N」全部指 `开发规范.md` 的对应条；调整该件编号时必须全仓搜「约定 #」同步改引用。

## 目录约定

```text
docs/
├── README.md                 # 本导航
├── 开发规范.md               # 业务侧约定 1–14（纪律与验收）
├── 框架索引.md               # 在哪里
├── 框架使用指南.md           # 怎么用
├── 框架开发参考手册.md       # 为什么这样设计
└── baseadmin设计精华参考.md  # 设计来源与目录规范
```

## 维护约定

1. 结构性变更（文件移动、新机制、新配置键）与代码同批更新索引。
2. 用户可见 API 变更同批更新使用指南，并完成前端、菜单种子与双构建门。
3. 公共文档不得写入内网主机、真实账号、初始密码、OTP 密钥或部署凭据。
4. 内部过程资料放在私有文档仓，不回流基础仓。
