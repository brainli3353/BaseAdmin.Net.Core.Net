# 项目地图（模板）——fork 后逐格填写

> **用途**：下游 fork 仓（IntelCore／FlowCore 类业务仓）接手时，用本模板把「资源在哪／凭据从哪来／怎么部署回滚／踩过哪些坑」四件事显式化，避免口口相传与"开发即生产"。
> **怎么用**：复制本件到目标仓 `docs/项目地图.md`，把每个 `<占位符>` 替换为该仓真实值；**填完即跑** `scripts/doctor.sh`（见 `templates/dotnet-repo/README.md`）。
> **凭据纪律**：本件**只写凭据来源**（在哪个文件／哪个环境变量／哪台机），**永不写凭据值**（口令、密钥、连接串明文一律不落文档）。默认口令一律标注「**仅开发默认，生产必改**」。

## 占位符清单

| 占位符 | 含义 | 示例格式 |
|---|---|---|
| `<APP_URL>` | 应用访问地址（测试/生产各一份） | `http://<host>:<port>` |
| `<BASE_URL>` | doctor 检查用的应用基址（通常＝`<APP_URL>`） | `http://127.0.0.1:5091` |
| `<LOGIN_URL>` | 登录端点完整地址 | `<BASE_URL>/api/auth/login` |
| `<DB_HOST>` / `<DB_PORT>` | 数据库主机 / 端口 | `<host>` / `5432` |
| `<DB_NAME>` | 数据库名（dev/test/prod 分列） | `<库名>` |
| `<REDIS_HOST>` / `<REDIS_PORT>` | 缓存主机 / 端口 | `<host>` / `6379` |
| `<DEPLOY_HOST>` | 部署机（SSH 别名，不写裸 IP） | `<ssh-alias>` |
| `<DEPLOY_DIR>` | 部署目录（clone／发布物落点） | `/data/deploy/<新仓名>` |
| `<SERVICE_NAME>` | systemd 服务名或容器名 | `<service>` |
| `<ENV_FILE>` | 宿主本地环境变量文件（凭据来源，不入仓） | `<宿主路径>/<env 文件>` |
| `<PORT>` | 应用监听端口 | `5090` |
| `<OTP_ISSUER>` | OTP 认证器条目 issuer（站点身份） | `<平台名>` |
| `<APP_NAME>` | 站点展示名（登录页／标题／issuer 同源） | `<平台名>` |

## 一、资源坐标（每个资源带一条可跑验证命令）

| 资源 | 坐标（本仓实际值） | 验证命令（可直接复制跑） |
|---|---|---|
| 应用（测试） | `<APP_URL>` | `curl -fsS <BASE_URL>/health` |
| 应用（生产） | `<APP_URL>` | `curl -fsS <BASE_URL>/health` |
| 数据库 | `<DB_HOST>:<DB_PORT>`／库 `<DB_NAME>` | `timeout 3 bash -c '</dev/tcp/<DB_HOST>/<DB_PORT>' && echo db-ok` |
| 缓存（Redis） | `<REDIS_HOST>:<REDIS_PORT>` | `timeout 3 bash -c '</dev/tcp/<REDIS_HOST>/<REDIS_PORT>' && echo cache-ok` |
| 部署机 | `<DEPLOY_HOST>` | `ssh <DEPLOY_HOST> hostname` |
| 部署目录／服务 | `<DEPLOY_DIR>`／`<SERVICE_NAME>` | `ssh <DEPLOY_HOST> systemctl status <SERVICE_NAME>` |
| OTP 配置状态 | issuer＝`<OTP_ISSUER>` | `curl -fsS <BASE_URL>/api/app/info` |

> 规则：每填一行坐标，**同批**写一条能在本机直接跑通的验证命令；跑不通的坐标＝没填完。

## 二、账号与凭据来源（只写来源，永不写值）

| 凭据／账号 | 来源（文件／环境变量／机器） | 说明 |
|---|---|---|
| 数据库连接串 | `<ENV_FILE>` 或环境变量 `<DB_CONN_ENV>` | 不入仓；生产走环境变量注入 |
| JWT 密钥 | 环境变量 `<JWT_SECRET_ENV>` | 全实例同值，否则用户随机掉线 |
| 加密密钥 | 环境变量 `<CRYPTOGRAM_KEY_ENV>` | 与库内密文绑定，换值即解不开 |
| Redis 连接串 | `<ENV_FILE>` 或环境变量 `<REDIS_CONN_ENV>` | 多实例部署必须 Redis 档 |
| 初始管理员账号 | 开发默认 `admin` / `Admin@123`（**仅开发默认，生产必改**）；生产口令来源＝`<ENV_FILE>` 或运维密码库 | 首次登录须扫码绑定 OTP |
| OTP issuer | 环境变量 `<OTP_ISSUER_ENV>` | 站点身份；改已绑定条目标签须重扫 |
| 部署／宿主凭据 | `<DEPLOY_HOST>` 本机 `<ENV_FILE>`（600，不入仓、不回显） | 部署脚本读取，不在仓内留值 |

> **一句话纪律**：文档只回答"**凭据在哪来**"，不回答"凭据是什么"——任何值出现在本件即违规。

## 三、部署与回滚 SOP

### 3.1 部署（幂等，可重复执行）

1. 前置：`<DEPLOY_HOST>` 上已备 `<ENV_FILE>`（600）与工具链。
2. 拉取：`git -C <DEPLOY_DIR> pull --ff-only`。
3. 构建：`<BUILD_CMD>`（前端构建＋后端 publish；具体命令见本仓 README）。
4. 切换：`<SWITCH_CMD>`（原子切换上一版）。
5. 健康门：`curl -fsS <BASE_URL>/health`，失败**自动回滚**上一版。
6. 留痕：记录部署 sha 与完成时间。

### 3.2 回滚（有可指名的回滚点）

1. 触发条件：健康门失败／关键接口 5xx／数据写入异常。
2. 回滚动作：`<ROLLBACK_CMD>`（切回上一版本目录；**只回滚应用，不回滚库**）。
3. 库侧：CodeFirst 增量建表**只加不删**——回滚旧版不会自动降列，需人工评估。
4. 回滚后：复跑 `scripts/doctor.sh`＋核对 `/health`。

### 3.3 每批必做

- 改配置 → 先备份 `<ENV_FILE>`，改后校验。
- 生产口径：`ApiDoc:Enabled=false`、密钥全走环境变量、凭据值不入仓。
